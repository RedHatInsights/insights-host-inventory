# Spec: RHINENG-17511

## Summary
Implementation specification for refactoring event and event header creation into a generic function for all EventTypes to reduce code duplication and improve maintainability. This document describes the plan; the actual code changes will follow in a subsequent implementation PR.

## Root Cause
Currently, constructing an event message and its corresponding headers requires multiple separate function calls (extract_system_profile_fields_for_headers, message_headers, and build_event) across several files in the codebase. This leads to redundant code patterns and increases the risk of inconsistencies when new EventTypes or header fields are introduced. Refactoring this into a single generic function will improve maintainability and code quality.

## Plan

- `app/queue/events.py` (modify): Add a new `build_event_and_headers` function that encapsulates the repeated pattern of calling `extract_system_profile_fields_for_headers`, `message_headers`, and `build_event`. The function should accept `event_type`, `host` (model instance for header extraction), an optional `serialized_host` (dict to pass to `build_event` instead of `host`), an optional `reporter` override, and `**kwargs` forwarded to `build_event` (e.g. `platform_metadata`, `initiated_by_frontend`). It should return a tuple of `(event, headers)`.
  - **`insights_id` handling**: The function must extract `host.insights_id` from the Host model instance and pass `str(host.insights_id)` to `message_headers`, preserving the existing string conversion currently performed at each call site.
  - **`reporter` handling**: When `reporter` is not explicitly provided (defaults to a sentinel like `_UNSET` rather than `None`, since `None` is a valid explicit value), the function must default to `host.reporter` (from the Host model instance). Callers may override this by passing an explicit `reporter` value (e.g. `output_host.get("reporter")` in `write_add_update_event_message`, or `message["host"].get("reporter")` in `sync_event_message`).

- `api/host.py` (modify): Refactor `_emit_patch_event` to use `build_event_and_headers` instead of separately calling `extract_system_profile_fields_for_headers`, `message_headers`, and `build_event`. The current call uses `host.reporter`, which matches the helper's default behavior (deriving reporter from the Host model), so no explicit `reporter` argument is needed. Update the imports to use `build_event_and_headers` from `app.queue.events` and remove the now-unused individual imports.

- `app/queue/host_mq.py` (modify): Refactor `sync_event_message`, `write_delete_event_message`, and `write_add_update_event_message` to use `build_event_and_headers` instead of separately calling the three functions. In `write_add_update_event_message`, pass `reporter=output_host.get('reporter')` and `serialized_host=output_host` to preserve the existing behavior (reporter comes from the serialized host dict, not the model). In `sync_event_message`, pass `reporter=message['host'].get('reporter')` (reporter comes from the inbound message payload). In `write_delete_event_message`, the current code uses `result.row.reporter` which matches the helper's default, so no explicit `reporter` is needed. Update imports to use `build_event_and_headers` and remove the now-unused individual imports (`build_event`, `extract_system_profile_fields_for_headers`, `message_headers`).

- `lib/group_repository.py` (modify): Refactor `_produce_host_update_events` to use `build_event_and_headers` with `serialized_host=serialized_host` instead of separately calling the three functions. The current code uses `host.reporter` and `str(host.insights_id)`, both of which match the helper's defaults, so no explicit overrides are needed. Update imports accordingly, removing `build_event`, `extract_system_profile_fields_for_headers`, and `message_headers`.

- `lib/host_synchronize.py` (modify): Refactor `_synchronize_hosts_for_org` to use `build_event_and_headers` with `serialized_host=serialized_host` instead of separately calling the three functions. The current code uses `host.reporter` and `str(host.insights_id)`, both of which match the helper's defaults, so no explicit overrides are needed. Update imports accordingly, removing `build_event`, `extract_system_profile_fields_for_headers`, and `message_headers`.

- `tests/test_host_mq_service.py` (modify): Update all mock patches that target the individual functions at the `app.queue.host_mq` namespace. Replace patches of `app.queue.host_mq.build_event`, `app.queue.host_mq.extract_system_profile_fields_for_headers`, and `app.queue.host_mq.message_headers` with a single patch of `app.queue.host_mq.build_event_and_headers` returning a tuple like `('event', {})`. This applies to approximately 5 test functions: `test_handle_message_failure_invalid_surrogates`, `test_handle_message_unicode_not_damaged`, `test_write_add_update_event_message_skips_deleted_host`, `test_write_delete_event_message_invalidates_cache`, and `test_write_delete_event_message_without_owner_id_skips_cache_invalidation`.

- `tests/test_unit.py` (modify): Add a test for `build_event_and_headers` that verifies it correctly combines header extraction, header building, and event building into a single call. Test with both created/updated events (which use a serialized host dict) and delete events (which use a Host model object). Verify the returned tuple contains a valid event string and correct headers dict.

## Constraints
- The existing public functions (build_event, message_headers, extract_system_profile_fields_for_headers) must remain in events.py since they are used in test helpers and other files (e.g. tests/helpers/mq_utils.py, utils/validate_hosts_for_delete.py)
- The exact structure and content of produced events and headers must not change — this is a pure refactor with no behavioral changes
